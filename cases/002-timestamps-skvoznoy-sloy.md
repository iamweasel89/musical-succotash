## Контекст

С самого начала проекта каждая сущность получала `createdAt`, некоторые — ещё `updatedAt`. Это воспринималось как «просто стандартная мета-информация модели». Галочка, не концепт.

Когда оператор задал прямой вопрос про слепоту LLM во времени, стало видно: timestamps **в данных есть**, но **LLM их не видит**. Промпту шёл только текст сообщения, без времени. Декораторы на UI — только абсолютное время, без чувства свежести. Для LLM каждый вызов — замороженный снимок без ощущения длительности или ритма.

## В запале

Добавить несколько доработок там, где «очевидно не хватает»:
- Показать «возраст» на пузыре (3 дня назад)
- В system prompt подшить текущую дату (уже было)
- На этом успокоиться — timestamps же есть в БД

Каждая правка — локальная, понятная, 15 минут.

## Выбрали

Выделить **сквозной слой времени**, разделив на две группы:

- **ВР — Время**: темпоральная осведомлённость AI. Не «дата на ноде», а всё что помогает модели ощущать момент, хронологию, намерения. Ритм сессии в system prompt. Timestamps в LLM-контексте при каждом вызове. Дедлайны и напоминания. Причинно-следственная логика.
- **ПМ — Память**: удержание прошлого и доступ к нему. Пересекается с ВР через хронологию, но шире — включает семантику (поиск по теме), компрессию (дайджесты), диффы.

Сразу же реализован **ВР-минимум**:
- Session tracker — помнит когда оператор открыл приложение
- System prompt расширен: part of day, workday/weekend, длительность сессии
- Каждое сообщение идёт в LLM с префиксом `[2 минуты назад]` / `[15 ч назад]` / абсолютная дата — модель видит хронологию
- `_formatBubbleTime` сам переключается: «только что / N мин / N ч / N дн» для свежих, абсолют для старых

## Открыло

- Родилась группа ПМ с 15 подпунктами (от persistent memory до дайджестов)
- Сценарий «[[СЦ-6]] ретроспектива по времени» стал формальным с понятным гэпом (ПМ1 persistent memory)
- Видно где timestamps ещё не хватает: event log действий, история настроек, жизненные события тезиса
- ВР4 напоминания (`flutter_local_notifications`) — через этот слой, не локальная фича
- Память-как-функции (глаголы: запомнить / забыть / укрепить / ослабить / связать / ранжировать) — стало возможно увидеть как следующий уровень
- Принцип «двухстадийного подъёма» проявился: первый climb (createdAt в моделях) дал данные; с высоты этого climb стал виден потолок (LLM слепа) и нужный кирпич (сквозной слой)

## Закрыло бы A

Если бы ограничились «датой на пузыре» и «сейчас в system prompt»:

- LLM всё равно не видела бы когда происходили события истории диалога (даты передавались бы только на верхнем уровне)
- Сценарий «что мы делали на прошлой неделе» оказался бы невозможен без отдельной инфраструктуры, построенной позже с нуля
- ВР4 напоминания воспринимались бы как отдельная фича Android-уведомлений, а не часть временного слоя
- Группа ПМ не появилась бы явно; когда понадобится persistent memory — обнаружится, что timestamps на событиях придётся переделывать ретроспективно
- Концепция «память-как-функции» не смогла бы родиться, потому что storage-модель осталась бы непроницаемой
