## Контекст

Оператор попросил встроить «сжать текст до N строк» через LLM. Технически — 15 минут работы: кнопка + вызов API + показ результата.

Напрашивалось: сделать отдельную группу бэклога «СЖ — Сжатие», реализовать кнопку только для одного места (сообщение веб-поиска), по мере надобности копировать в другие места.

## В запале

Сделать **compress как отдельную фичу**. Одна кнопка, одно место вызова, одна функция `compressText(text, N)`.

Это было бы быстро и сразу работало. Но:

- Thesis-формулировка уже делает похожее («перефразируй фрагмент как один тезис») — дубль логики
- Translate, rewrite, outline, TL;DR — все это LLM-трансформации текста по инструкции. Пришли бы по одной, каждая со своей кнопкой и своей функцией
- Пяти дублей избежать бы не удалось; связать их потом — дороже чем сразу выделить общий слой

## Выбрали

Выделить **общий слой ПТ — Преобразование текста**:

- **Ядро**: `llmTransform(text, instruction, settings) → Future<String>` — один вызов LLM по произвольной инструкции, независимо от конкретной задачи
- **Пресеты поверх ядра**: `compress(N)` / `tldr` / `translate(lang)` / `rewriteFormal` / `outline`
- **Единая compress-шторка** как переиспользуемый UI-виджет — long-press в чате, тезис-карточках, веб-поиске, debug-панели
- **Агентский tool** `llm_transform` для LLM — модель сама может сжать длинный `web_extract` перед продолжением reasoning

Тезисная формулировка при этом становится тонкой обёрткой над тем же ядром (см. ПТ5 в паспорте).

## Открыло

- Любой новый тип трансформации = один пресет над готовым ядром (10 строк)
- LLM-агент сам управляет своим контекстом: видит что пришёл огромный `web_extract` → вызывает `llm_transform` с инструкцией «выдели ключевое» → продолжает с компактным
- Группа [[002]] (время) родилась в том же ключе: не «добавить date» на ноде, а **сквозной временной слой**
- Группа РГ (развёртывание — один-ко-многим) появилась как естественный дополнительный контракт над тем же ядром
- Рождается принцип «кирпичи, не продукты»: каждая новая функция оценивается и как кирпич — что на ней ещё может вырасти

## Закрыло бы A

Если бы пошли в запале:

- Thesis-мод сохранил бы свою отдельную LLM-инфраструктуру; через месяц — два почти одинаковых HTTP-клиента на один и тот же эндпоинт
- Translate/rewrite/outline/tldr — каждый появлялся бы как новый тикет без общего места; UI плодил бы кнопки
- РГ (дивергентная генерация) пришлось бы выдумывать заново, не увидев её связи с ПТ
- Первый «большой» рефактор начали бы только когда количество дублей начнёт мешать жить. К тому времени — 4–5 несовместимых кусков, каждый с тестами
