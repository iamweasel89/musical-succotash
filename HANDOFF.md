## Компас

Определение молекулы — в `MOLECULE.md`. Короткая форма:

- **Молекула (ход)** = один API-вызов LLM. Механика, не замысел.
- **Атом** = один `.md`-файл с YAML-frontmatter + телом.
- Три инварианта: ход не редактируется; атом редактируется с updated; один ход = один API-вызов.
- Поле `source_move_id` в атоме, `parent_move_ids` и `context_refs` в ходе — lineage.
- Lineage считается в UI: `depth` — длина цепочки по предкам, `manual_depth` — длина непрерывной manual-подцепочки.

## Что реализовано

- Минимальный Flutter-APK с seed-атомом (компас виден изнутри приложения).
- Отправка промтов через поле ввода → API Anthropic → предпросмотр → «Сохранить» (gate=manual) / «Отбросить».
- Быстрая запись без LLM (📝 иконка).
- Контекст-пикер (📎 иконка): выбрать атомы → отправить вместе с промтом; их source_move_ids попадут в parent_move_ids нового хода.
- Debug HTTP-сервер на порту 8080 с токен-авторизацией:
  - `GET /vault/list` — все атомы и ходы
  - `GET /vault/atoms/:id`, `GET /vault/moves/:id` — чтение
  - `POST /vault/atoms` — записать атом
  - `POST /vault/prompt` (body: `{prompt, context_atom_ids?}`) — полный цикл auto-хода
  - `POST /input/stage` — подсунуть текст в поле ввода для оператора
  - `DELETE /vault/atoms/:id`, `DELETE /vault/moves/:id`
- Updater с отображением текущего билда и доступного рядом.
- Дашборд как главный экран: статистика, последние 3 атома, последняя цепочка (горизонтальная лента), кнопки «Все атомы / Все ходы» → `VaultListScreen`.
- В `VaultListScreen` есть сортировка ходов по времени / глубине / чистой глубине.
- Просмотр атома/хода: markdown-рендер, чипы метаданных, кликабельные ссылки `source_move_id`, `parent_move_ids`, `children`, `context_refs`, `result_refs`.

## Связь с телефоном (режим совместной работы)

- На Windows машине оператора поднят Tailscale Funnel на адрес Windows, который проксит через Tailscale на телефон.
- **Публичный URL**: `https://windows-3tm8vsu.tail60e676.ts.net`
- **Токен**: `X-Debug-Token: tok_hhrsofczk7`
- Проверка контакта: `GET /vault/list` должен вернуть JSON.
- Если токен утечёт или надоест — перегенерировать в Настройки → Debug HTTP-сервер → иконка ↺ рядом с токеном. В этом файле обновить вручную.
- Запись атома за оператора: `POST /vault/atoms` с body `{"type": "note", "body": "…"}`.
- Подставить промт в поле ввода: `POST /input/stage` с body `{"prompt": "…"}` (оператор сам нажмёт «Отправить» после pull-to-refresh).
- Полный auto-цикл: `POST /vault/prompt` с body `{"prompt": "…", "context_atom_ids": ["…"]?}`. Пишет в волт без предпросмотра оператора — использовать **только с явного разрешения**, иначе нарушится принцип manual-валидации.

## Принципы, к которым мы пришли

1. **Молекула** — единица системы. Не «чат», не «заметка», а ход с провенансом.
2. **Механика первична, замысел эмерджентен.** Не требовать от оператора формулировать «intent» как обязательное поле. Замысел находится ретроспективно, по узорам в ходах.
3. **Удаляй раньше, чем автоматизируешь** (Маск). Перед добавлением фичи — проверка: не упрощается ли задача удалением чего-то.
4. **Не тащи то, исходники чего не понимаешь** (Кармак). При выборе зависимостей.
5. **Bitter Lesson**: не изобретать эвристик поверх LLM. Давать инструменты, доверять масштабу.
6. **Если не понимаешь, почему работает — не понимаешь, что делает** (Блоу).
7. **Зыбкость чувства «что-то не так» — сигнал, не шум.** Слушать, не гасить.
8. **Ход = один API-вызов.** Цепочка из нескольких вызовов — это цепочка ходов, не один «умный» ход. Провенанс каждого звена отдельно.
9. **Gate=manual даёт накопленную валидацию.** Цепочка из N manual-звеньев — N утверждений оператора. Auto-цепочки — разведка, не валидация.

## Стиль работы с оператором

- Оператор **не кодер**. Разбираться в коде не будет.
- Имеет **доЛЛМ-ный инженерный опыт** в координации/управлении. Хорошее чутьё на неправду.
- Доверяет, но **проверяет по ощущению**: если что-то ощущается «не своим» — говорит вслух, надо слушать.
- **Не объясняется и не оправдывается** за темп, скорость, и вопросы типа «почему так долго». Это off-limits для помощи.
- Разрешает auto-режим («пишешь всё сам») только после явного утверждения. По умолчанию — stage-режим (я кладу промт в поле ввода, оператор нажимает ➤).
- **Нумерация ответов**: в начале каждого ответа — `**N. [YYYY-MM-DD HH:MM]**`, время по Europe/Bratislava через `TZ="Europe/Bratislava" date +"%Y-%m-%d %H:%M"`. Последний номер из `sessions/<дата>.md` плюс один. Если нет файла — продолжать с номера, достигнутого в предыдущей сессии.
- **Длительность проекта**: ветка substrate/v1 начата 2026-04-20, ей один день. Не выдумывай цифры; при любом вопросе про время — `git log`, не внутреннее ощущение.
