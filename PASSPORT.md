## Что приложение делает

Мобильный клиент. Навигация — два таба:
- **Канва** — гексагональная сетка, ноды (текст/API), рёбра, мультиканвас
- **Чат** — ветвящийся диалог с LLM, каждое сообщение = нода на канве

Плюс **Мастерская** (вход из настроек) — экран-хаб с комнатами: извлечение отрывков, режим тезисов, дерево решений, инбокс, веб-поиск, справка, отладка.
Поиск по нодам — из тулбара главного экрана.

## Протокол работы

### Стиль общения
- Без вступлений, без резюме вопроса, без "конечно!".
- Оператор прыгает между темами — AI удерживает каждую как малый контекст.
- Краткость по умолчанию. Подробности — по запросу.

### Маркировка ответов
Каждый ответ AI начинается с номера в **bold**: **1**, **2**...
Нумерация сквозная в пределах сессии; новая сессия — с **1**.
Секции внутри ответа: **12а**, **12б**. Оператор ссылается: «re: 12б» — однозначно указывает на ответ и раздел.
При просьбе промаркировать задним числом — AI выписывает последние N ответов с присвоением номеров.

### Маркировка задач
Задачи кодируются буквой группы + номером: Г1, Я2, Э3.
Оператор говорит "делай Я4" или "Я5 в закладки" — без расшифровки.

### Стопка
Список задач для следующего спринта. Формат:
```
**Группа — название**
- КОД  название — одна строка: что делает
- *КОД  название — префикс `*` = срочное
```
Подробности раскрываются только по запросу "раскрой X".
Порядок выполнения не предлагается если не спросили.

### Ключевые слова
- **В закладки** — отложено, не потеряно, вернёмся
- **Стопка** — дай следующую партию задач
- **Строже** — критический разбор, не щадить
- **Черновик** — сырая мысль оператора, сохранить as-is
- **Паспорт** — канонический статус документа, не имя шага
- **Вбок** — оператор временно уходит в соседнюю тему. AI запоминает текущий контекст как точку возврата, берёт новую тему на малый контекст. Текущая задача не считается брошенной.
- **Возвращаемся** — явный триггер вернуться к ранее отложенной теме. AI поднимает последний контекст помеченный «вбок».

### Протокол логов (отладка экстрактора)
- Повторяющаяся запись = оператор подтвердил баг (приоритет)
- Единственная запись = гипотеза AI (менее важно)

### Пуш
Часть конвейера. После готовой задачи: коммит → пуш → сообщи хэш → дальше.

### Слабые пункты бэклога
При обзоре: если пункт — дубль или тривиальщина, удалять без сожалений. Если идея без ясной цели — в раздел «Сырой резерв» ниже Бэклога. Бэклог остаётся списком задач с обоснованием. Резерв пересматривать раз в квартал: появился сценарий → обратно в бэклог; простоял — удалить.

### Сценарии как вход в бэклог
Новая задача в бэклоге обязана иметь обоснование — короткий сценарий «когда оператор делает X, ему нужно Y». Без сценария — пункт идёт в «Сырой резерв», не в бэклог. Сценарии копятся в разделе «Сценарии» ниже с перекрёстными ссылками на задачи. При ревизии пункта задаётся вопрос «какой сценарий обслуживает?» — нет ответа → в резерв.

### Консоль вместо ручной возни с файлами
Любые скрипты, конфиги, .ps1/.bat/.json и прочие файлы на машине оператора создаются и наполняются **одной командой из консоли** (Set-Content / Out-File / heredoc). Инструкция «открой файл X, вставь Y» недопустима — всегда даём pastable command.

## Срочные задачи (раскрыть при обращении)

**ПТ — Преобразование текста** *(общий слой LLM-трансформаций: ядро для Я / БК3 / агента)*
- ПТ1 ✓ ядро `services/llm_transform.dart` — функция `llmTransform(text, instruction, {maxTokens, temperature})`; поддерживает anthropic/openai/deepseek; выбор provider/model из `settings.defaultProvider/defaultModel` или override
- ПТ2 ✓ пресеты — `compress(text, N)` / `tldr(text)` / `translate(text, lang)` / `rewriteFormal(text)` / `outline(text)`
- ПТ3 ✓ compress-шторка доступна из нескольких мест: (а) long-press на сообщении веб-поиска → «Сжать…», (б) иконка compress в action-row чат-пузыря, (в) иконка compress рядом с формулировкой/ответом тезиса с применением результата, (г) универсальная панель «Сжать любой текст» в Мастерская → Отладка. Text-node-sheet пропущен — не используется; node_panel требует прокидывания settings от верхнего экрана, отдельной задачей.
- ПТ4 ✓ агентский tool `llm_transform(instruction, text)` — агент может сжимать длинные результаты extract/crawl
- ПТ8 метаданные у compress-результата — `createdAt + sourceNodeId + sourceLength + N`; след трансформации, чтобы оператор и AI видели откуда и когда получен текст
- ПТ5 миграция тезисов на пресеты — `thesisFormulate(excerpt)` и `thesisAnswer(thesis)` становятся тонкими обёртками над ПТ ядром
- ПТ6 пользовательские пресеты — оператор добавляет свои инструкции в настройках (плейсхолдер `{text}`, опц. `{N}`)
- ПТ7 интеграция с БК3 — mini-summary при «вбок» использует `compress(thread_text, 3)`

**РГ — Развёртывание / дивергентная генерация** *(один вход → N выходов; канва-метафора: N дочерних нод)*
- *РГ1 ядро `services/llm_fanout.dart` — `llmFanout(text, instruction, {n, temperature})` → Future<List<String>>; использует OpenAI `n=N` / Anthropic параллельные запросы / пресет-промпт «дай N вариантов»
- РГ2 пресеты — `alternatives(text, n)` / `brainstorm(topic, n)` / `perspectives(text, angles)`
- РГ3 action на пузыре/ноде → «Дай N вариантов», чипы 3/5/10
- РГ4 UI отображения — чипы-переключатели ◀▶ в ноде (Я3 style) или N дочерних нод на канве; выбор режима в настройках
- РГ5 унификация с Я3 и Н2 — мигрировать их на РГ (см. перекрёстные ссылки)
- РГ6 агентский tool `llm_fanout(instruction, n)`
- РГ7 слайдер температуры — «насколько разные варианты» (0.3 vs 0.9)

**Я — Тезисы (ядро)** *(workflow-группа: карточки, excerpt→thesis→answer; внутри использует ПТ — см. ПТ5; варианты — см. РГ5)*
- Я1 ✓  LLM-формулировка тезиса — кнопка на карточке → ApiRunner → entry.thesis
- Я2 ✓  свайп на пузыре → тезис — ExcerptExtractor с onConfirm
- Я3  история вариантов тезиса — ◀▶ на карточке, макс 5, эфемерно (через РГ — см. РГ5)
- Я4  редактируемый промпт формулировки — GlobalSettings, плейсхолдер {excerpt}
- Я5 ✓  свайп-выделение на пузыре (раскрытие Я2) — через ExcerptExtractor
- Я6  контекст ±N слов вокруг excerpt — окно из source-ноды, теги
- Я7 ✓  LLM-ответ на тезис — кнопка ⚡ у поля «Ответ»
- Я8  tap-to-source — стрелка на карточке скроллит к пузырю, подсветка

## Бэклог

**У — Управление тезисами**
- У2  метка на пузыре "уже в тезисах" + флаг в настройках
- У3  добавить целый пузырь как тезис без выделения

**О — Инбокс**
- О1  промпт для LLM-разбора черновиков (текст готов в Ключевых концепциях)
- О2 ✓  экран просмотра inbox/ внутри приложения
- О3  первый ручной прогон дерева концептов

**К — Конвейер**
- К1  режим источника — двойной вид (чат + канва), выбор нод/сообщений, кнопка "утвердить"
- К2  страница синтеза — "что делаем с кусочками", отдельная глава режима
- К3  синтез-нода — результат LLM-синтеза как нода особого типа в канве

**П — Паспорт как сущность**
- П1  действие "сделать паспортом" — повысить документ до канонического статуса

**ПО — Поисковый агент**
- ПО1 ✓ ключ Tavily в настройках приложения
- ПО2 ✓ агентский цикл — `services/agent_runner.dart`, tool_use для Anthropic/OpenAI/DeepSeek
- ПО3 ✓ инструмент web_search — Tavily основной, DuckDuckGo резерв
- ПО4 ✓ ротация поисковых провайдеров — Tavily→DDG при отсутствии ключа / 401 / 429 / ошибке / 0 результатов, с пояснением в логе комнаты

**Р — Разделка дампов**
- Р1  обработка дампа в экстракторе — загрузить inbox-файл как источник текста

**Н — Итерация синтеза**
- Н1  повторный проход — взять готовый документ + новые фрагменты → ре-синтез

**З — Связи**
- З1  теги на документах/паспортах — Obsidian-стиль, поиск по тегам
- З2  тезис → нода канвы — тезис о конкретной ноде визуально к ней привязан

**Б — База / поиск**
- Б1  поиск по инбоксу внутри приложения
- Б2  поиск по сообщениям в чате

**М — Мастерская как среда разработки**
- М1 ✓  перенести режим тезисов из чата в Мастерскую — тезисы как самостоятельное пространство
- М2 ·▲ Мастерская как встроенная среда разработки — Claude Code внутри приложения, контекст графа доступен AI, оператор и AI смотрят на одну канву

**Т — Дерево решений**
- Т1 ✓ модель данных — DecisionEntry (тип, статус, заметки, parentId)
- Т2 ✓ экран в Мастерской — плоское дерево с отступами, статусные точки
- Т3  быстрое добавление из тезиса / пузыря
- Т4 ✓ экспорт дерева — markdown с вложенностью
- Т5  связь с нодой канваса

**БК — Боковые ветки (многонаправленный чат)** *(ядро — передать LLM параллельный фокус)*
- *БК1  мульти-активные треды — пул из 2-5 выбранных цепочек одновременно; тап на ноде добавляет/убирает её цепь из «активного пула»
- *БК2  системный промпт расширяется — в каждый LLM-вызов: текущий тред целиком + мини-выжимки остальных активных тредов (то что раньше было невидимо — становится малым контекстом для модели)
- БК3  mini-summary при паузе — «вбок» триггерит генерацию LLM короткой выжимки текущего треда (использует ПТ пресет `compress` с N=3); именно её потом поднимают без повторения всего
- БК4  визуализация параллельности — лента/панель активных и паузных тредов: что в фокусе, что дремлет, как выглядят выжимки
- БК5  протокол «вбок/возвращаемся» как команды UI — жест в чате (свайп/long-press) триггерит БК3 + добавляет тред в пул с флагом paused
- БК6  cross-chain references — «применить Я3 сюда» заставляет систему пробросить фрагмент другой цепочки в контекст активной
- БК7  устойчивость сессии — после разрыва/перезапуска пул активных тредов восстанавливается, все выжимки живы
- БК8  разбор: что из этого уже покрывается мультиканвасом и ветвлением, а что нет; состыковать с группами А (асинхронный) и Г (граф)

**ЛЧ — Летающий чат-помощник** *(интерактив, поверх приложения)*
- *ЛЧ1  плавающий оверлей с мини-чатом — всегда на экране, не мешает работе, можно свернуть
- ЛЧ2  AI видит контекст оператора (текущий экран, последний тап, выделенный элемент) — через debug-сервер или прямой bind
- ЛЧ3  подсказки в реальном времени: оператор открыл ноду → AI сразу предлагает «продолжить», «сравнить с похожей», «в тезисы»
- ЛЧ4  короткий ответ в оверлее, полный — разворачивается в отдельный экран
- ЛЧ5  разбор архитектуры: overlay как Flutter-виджет vs системный бабл (Android bubbles API)

**ВИ — Видимость AI** *(в системе гексов, не только дебаг)*
- ВИ1 ✓ фаза 1: tap-to-share — кнопка «Показать Claude» в тулбаре → Android Share sheet со state JSON + скриншотом; оператор шарит в Claude Code / чат; без хостинга, без фонового трафика
- ВИ2  туннель / публичный endpoint по кнопке в приложении — уже сделано через Мастерская → Отладка (debug-сервер + Tailscale Funnel); потенциально унифицировать с ВИ1
- ВИ3 ✓ встроенная кнопка «показать AI что я вижу» — тулбар MainScreen, `Icons.ios_share`
- ВИ4 ✓ архитектура решена: гибрид (pull через Funnel + push tap-to-share). Continuous observe / авто-события — отложены в дальний угол (фаза 2)
- ВИ5  аудит того что AI реально видит (без API-ключей, без приватного текста если флаг)
- ВИ6  change-detect режим для скриншотов ПК (сервер копит hash'и, я poll-ю /status):
  - ВИ6.1  фоновая петля hashing в PC-сервере (дефолт 2 сек, интервал в env-var)
  - ВИ6.2  endpoints /status (hash+ts) и /changes?since=<hash>
  - ВИ6.3  perceptual hash (pHash) вместо SHA — игнорировать шум, анимации часов

## Сценарии

Банк операционных историй «когда это нужно». Каждый сценарий → одна или несколько задач бэклога (перекрёстные ссылки в поле «Порождает»). Формат:

```
### СЦ-N Название
Контекст:  [что делает оператор, в какой момент]
Проблема:  [что сейчас неудобно или невозможно]
Желаемое:  [как должно быть]
Порождает: [коды задач бэклога]
```

### СЦ-1 Возврат к давно оставленной теме
Контекст:  оператор помнит что обсуждал с AI что-то неделю назад, но не помнит в какой цепочке / канвасе / тезисах.
Проблема:  нет retrieval по времени или теме; нет дайджестов; всё плоско.
Желаемое:  спросить «что я делал на прошлой неделе» — получить список-резюме со ссылками на ноды.
Порождает: ПМ2, ПМ3, ПМ4, ПМ10, Б1.

### СЦ-2 Сжать шумный тред
Контекст:  оператор накидал 30 сообщений размышлений, значительная часть — шум.
Проблема:  хочет оставить 3-5 ключевых тезисов, остальное свернуть или убрать.
Желаемое:  нажал «сжать тред» → получил выжимку, исходные сообщения визуально коллапсируются.
Порождает: ПТ3 (compress), БК3 (mini-summary), Г5 (коллапс цепочки).

### СЦ-3 Параллельная тема без потери фокуса
Контекст:  оператор в процессе раскрытия идеи X вспоминает связанное с темой Y.
Проблема:  «отвлечься» = новая ветка чата = потеря фокуса основной; AI не помнит куда вернуться.
Желаемое:  «вбок» на 5 минут → вернулся → AI продолжает X с места, Y сохранён параллельно.
Порождает: БК1, БК2, БК3, БК5.

### СЦ-4 Устаревшая информация
Контекст:  оператор цитирует факт или ссылку которую AI дал месяц назад.
Проблема:  AI не предупреждает что факт мог устареть; pretends it's fresh.
Желаемое:  у старых фактов пометка «проверено N назад»; AI в ответе сам отмечает «устаревшее».
Порождает: ПМ8, ВР7.

### СЦ-5 Быстрый синк с Claude Code (реализовано)
Контекст:  оператор тестирует фичу на мобильном, хочет показать Claude что происходит.
Проблема:  либо описывать словами (медленно, теряется контекст), либо скриншот руками.
Желаемое:  один тап в тулбаре → Android Share → Claude получает state + screenshot.
Порождает: ВИ1 ✓, ВИ3 ✓.

### СЦ-6 Ретроспектива по времени
Контекст:  оператор спрашивает «что мы делали в такой-то момент / период» (напр. «сегодня в 3 ночи»).
Проблема:  сейчас AI может поднять только ОДИН источник (git commits) через внешний инструмент; ноды канвы, тезисы, решения, inbox-файлы имеют timestamps, но в единый индекс не собираются; обсуждения с AI не фиксируются вовсе.
Желаемое:  запрос «что было в X» → агрегат со всех источников (git + канва + inbox + theses + decisions + история разговоров), сортированный по времени.
Порождает: ПМ1 (persistent memory), ПМ15 (timeline-view), ПМ12 (event log), + git как внешний источник. Главный гэп — ПМ1.

## Ключевые концепции

**Три уровня документа:**
черновик (сырая запись) → документ (синтез) → паспорт (канонический статус)

**Инбокс:** `documents/inbox/` — накопитель черновиков и тезисов для последующего LLM-разбора.

**Промпт разбора инбокса:**
> Вот записи оператора. Извлеки все концепты, функции, протоколы, решения.
> Для каждого: тип (функция/концепт/протокол/дизайн), статус (готово/черновик/очередь/обсудить/идея), одна строка. Выдай деревом.

**Режимы LLM-синтеза:** текст, JSON, outline/дерево, Q&A, теги, код, аннотация.

**Асинхронный режим:** оператор ведёт несколько тем параллельно без вступлений. AI держит каждую отдельно.
